# mathtutor

*[Русская версия](README.md)*

A console math tutor for first-year students. It **generates problem variants, checks answers and explains which typical mistake you made**, then picks the next problem to match your level.

```
> 72
Неверно.
Похоже на типичную ошибку: вы посчитали размещения (порядок учтён), а нужны сочетания:
комиссия из тех же людей в другом порядке — та же комиссия.
```

(Wrong. This looks like a typical mistake: you counted arrangements, where order matters, but combinations are needed: a committee of the same people in a different order is the same committee.) The interface language is Russian.

## What kind of "AI" this is

This is **not a neural network and does not call a language model**. It is a classical tutoring system built on two ideas:

1. **A model of typical mistakes (buggy rules).** For each problem the program precomputes which wrong answers result from popular mistakes: a flipped sign in a determinant, order taken into account where it does not matter, and so on. If your answer matches one of them, the program names the mistake and explains it. The result is deterministic and every rule can be tested.
2. **A knowledge model (Bayesian Knowledge Tracing, BKT).** For each topic it keeps the probability that you have mastered it. After every problem the estimate is updated with Bayes' rule, accounting for slips and guesses. It also decides which topic and difficulty to offer next.

Why not an LLM: here the correctness of the mathematics has to be guaranteed rather than hoped for. Answers are checked with exact arithmetic and mistakes are diagnosed by rules covered by tests.

## Quick start

Python 3.10+ is required (tested on 3.13); there are no dependencies.

```bash
git clone https://github.com/EminChyldyrly/mathtutor
cd mathtutor

python -m mathtutor practice -n 5          # interactive practice, progress is saved
python -m mathtutor report                 # topic mastery and frequent mistakes
```

The same features without interaction, handy for self-checks or scripts:

```bash
python -m mathtutor topics
python -m mathtutor task det --difficulty 2 --seed 3          # a problem (the same seed gives the same problem)
python -m mathtutor hint det --difficulty 2 --seed 3 2        # the second hint
python -m mathtutor check det --difficulty 2 --seed 3 -85     # check an answer
python -m mathtutor task det --difficulty 2 --seed 3 --solution
```

`check` returns exit code 0 for a correct answer, 1 for a wrong one and 2 if the answer could not be parsed. In a `practice` session: `h` shows a hint, `s` shows the solution, `q` quits. Progress is stored in `~/.mathtutor.json` (another path: `--profile`).

Real output examples: [docs/session.md](docs/session.md) (a whole session with a report) and [docs/diagnosis.md](docs/diagnosis.md) (one diagnosis example per topic). Both files are generated by `python scripts/make_docs.py`.

## Topics

| Topic | `id` | What the problems contain | Typical mistakes that are recognised |
|---|---|---|---|
| Determinant | `det` | 2×2 and 3×3 matrices | opposite sign; main diagonal only; diagonal products added; all Sarrus terms with "+"; signs not alternating in row expansion |
| Systems of equations | `system` | 2 and 3 unknowns, unique solution | values of the unknowns swapped; a sign error in one unknown. Plus a substitution check: which equations are not satisfied |
| Combinatorics | `comb` | combinations, arrangements, repetition, permutations of the letters of a word | order counted where it does not matter; order ignored where it matters; repetition allowed where there is none; repetition forbidden where it is allowed; identical letters not accounted for; an error in the formula C(n+k−1, k) |
| Properties of relations | `rel` | 3–4 elements, four properties | antisymmetry mistaken for "not symmetric"; reflexivity from a single loop; transitivity without the cases of coinciding elements. Plus a counterexample for each wrong claim |

Every problem has three levels of hints, from the general method to an almost finished step, and a full solution on request. Answers are accepted in several notations: `-3`, `1/2`, `(2; 5; 1)`, `x=2, y=5, z=1`, property names in words.

## How it is built

```
mathtutor/
  topics/            four topics: problem generation, answer parsing, typical mistakes, hints, solution
    base.py          Topic, Task, Malrule; exact number parsing
  tutor.py           answer checking with diagnosis, problem selection, interactive session, report
  bkt.py             mastery estimate update, difficulty selection
  profile.py         the learner profile in JSON (atomic writes, format validation)
  cli.py             command line
scripts/make_docs.py generator for docs/
tests/               80 tests
```

Principles everything rests on:

- **Problems are deterministic.** A problem is defined by the triple (topic, difficulty, seed), so it can be reproduced. Verified in separate processes under different `PYTHONHASHSEED` values.
- **Answers are always checked exactly.** Numbers are stored as fractions; there are no floating-point comparisons.
- **Unreadable input is not a learner mistake.** If you mistype (`abc`, `1/0`), the attempt is not counted and the knowledge model ignores it.
- **One answer is one observation.** BKT gets one record per problem: "correct on the first attempt and without hints" or not.
- **Diagnosis is cautious in its wording.** The same number can come from different mistakes, or from chance, so the program says "looks like a typical mistake" rather than asserting. If several rules fit, all are shown.

## How it is verified

80 tests with the standard `unittest`, running in a fraction of a second: `python -m unittest discover -s tests -v`.

- **Problems are checked against independent implementations.** Determinants against Laplace expansion, combinatorics against `itertools` enumeration, relation properties against textbook definitions, system solutions by substitution into the equations.
- **Diagnosis is tested in both directions.** For every "buggy rule", the answer it produces is recognised and receives its own explanation. Every described rule occurs in real problems. Wrong-answer values for combinatorics are compared with an independently written list of wrong formulas, and for the other topics checked on precomputed examples.
- **The knowledge model is compared with Bayes' formula** computed separately in exact fractions; the [0, 1] bounds and convergence are checked.
- **Robustness to garbage.** Random strings are fed to the parsers of all topics and must not raise exceptions. This is how a crash on the input `1/0` was found.
- **Profile.** Round-trip write and read; a corrupted file is not overwritten; a failure in the middle of a write does not damage the old profile.
- **The tests themselves were tested.** I introduced 26 typical bugs into the code (a flipped sign, an off-by-one, a missing condition, wrong thresholds) and confirmed that the tests fail on each. Three survived the first time, and checks were added for them. This battery tests the tests; it does not prove the absence of bugs.

## Limitations

- **Only the final answer is recognised.** The program does not see the course of your solution: it will notice that "the sign flipped" but not at which step. An arithmetic slip that matches no known rule gets only "Wrong".
- The list of typical mistakes was compiled by me from experience with textbook problems, not derived from data on real students.
- **BKT parameters** (`p_init = 0.2`, `p_learn = 0.15`, `p_slip = 0.1`, `p_guess = 0.2`) were chosen as reasonable defaults, not trained on data. Read the mastery estimates as a rough guide.
- Four topics, three difficulty levels, Russian language, one user per profile file.
- A problem that was started and abandoned (for example, quitting after a hint) counts as a failure.

## Ideas for development

- checking the **course of the solution**: accept intermediate steps and find where the mistake is (this links naturally to my mathsteps project, which can already build a reference solution step by step);
- training the BKT parameters and the list of typical mistakes on logs of real sessions (the profile already stores the history);
- spaced repetition: bring topics back on a forgetting schedule;
- a language model as an *explanation layer* on top of the verified diagnosis: it phrases the explanation, while correctness is still decided by the code.
