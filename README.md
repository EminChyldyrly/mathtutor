# mathtutor

*[English version](README.en.md)*

Консольный тренажёр по математике для первых курсов. Он **генерирует варианты задач, проверяет ответы и объясняет, какую именно типичную ошибку вы допустили**, а потом подбирает следующую задачу под ваш уровень.

```
> 72
Неверно.
Похоже на типичную ошибку: вы посчитали размещения (порядок учтён), а нужны сочетания:
комиссия из тех же людей в другом порядке — та же комиссия.
```

## Что это за «ИИ»

Это **не нейросеть и не обращение к языковой модели**. Это классическая обучающая система, построенная на двух идеях:

1. **Модель типичных ошибок (buggy rules).** Для каждой задачи программа заранее вычисляет, какие неверные ответы получатся при популярных ошибках метода: перепутанный знак в определителе, учтённый порядок там, где он не важен, и т. д. Если ваш ответ совпал с одним из них, программа называет ошибку и объясняет её. Результат детерминирован, и каждое правило можно проверить тестом.
2. **Модель знаний (Bayesian Knowledge Tracing, BKT).** Для каждой темы хранится вероятность того, что вы её освоили. После каждой задачи она обновляется по формуле Байеса с учётом ошибки по невнимательности и угадывания. От неё зависит и то, какую тему и какой сложности предложить дальше.

Почему не LLM: правильность математики здесь нужно гарантировать, а не надеяться на неё. Ответ проверяется точной арифметикой, а ошибка диагностируется по правилам, которые покрыты тестами.

## Быстрый старт

Нужен Python 3.10+ (проверено на 3.13), зависимостей нет.

```bash
git clone <ссылка на этот репозиторий>
cd mathtutor

python -m mathtutor practice -n 5          # интерактивная тренировка, прогресс сохраняется
python -m mathtutor report                 # освоение тем и частые ошибки
```

Те же возможности без интерактива, удобно для проверки себя или скриптов:

```bash
python -m mathtutor topics
python -m mathtutor task det --difficulty 2 --seed 3          # задача (тот же seed даёт ту же задачу)
python -m mathtutor hint det --difficulty 2 --seed 3 2        # вторая подсказка
python -m mathtutor check det --difficulty 2 --seed 3 -85     # проверить ответ
python -m mathtutor task det --difficulty 2 --seed 3 --solution
```

`check` возвращает код 0 для верного ответа, 1 для неверного и 2, если ответ не удалось разобрать. В сеансе `practice` команды: `h` — подсказка, `s` — показать решение, `q` — выйти. Прогресс хранится в `~/.mathtutor.json` (другой путь: `--profile`).

Примеры реального вывода: [docs/session.md](docs/session.md) (целый сеанс с отчётом) и [docs/diagnosis.md](docs/diagnosis.md) (по одному примеру диагностики на тему). Оба файла генерируются `python scripts/make_docs.py`.

## Темы

| Тема | `id` | Что в задачах | Типичные ошибки, которые распознаются |
|---|---|---|---|
| Определитель | `det` | матрицы 2×2 и 3×3 | противоположный знак; только главная диагональ; произведения диагоналей сложены; все слагаемые Саррюса со знаком «+»; в разложении по строке не чередуются знаки |
| Системы уравнений | `system` | 2 и 3 неизвестных, единственное решение | значения неизвестных перепутаны местами; ошибка в знаке одной неизвестной. Плюс разбор подстановкой: какие именно уравнения не выполняются |
| Комбинаторика | `comb` | сочетания, размещения, повторения, перестановки букв слова | учтён порядок, который не важен; не учтён порядок, который важен; разрешены повторы, которых нет; запрещены повторы, которые допустимы; не учтены одинаковые буквы; ошибка в формуле C(n+k−1, k) |
| Свойства отношений | `rel` | 3–4 элемента, четыре свойства | антисимметричность принята за «не симметричность»; рефлексивность по одной петле; транзитивность без случаев с совпадающими элементами. Плюс контрпример к каждому ошибочному утверждению |

У каждой задачи три уровня подсказок, от общего метода к почти готовому шагу, и готовое решение по запросу. Ответы принимаются в разных записях: `-3`, `1/2`, `(2; 5; 1)`, `x=2, y=5, z=1`, названия свойств словами.

## Как устроено

```
mathtutor/
  topics/            четыре темы: генерация задачи, разбор ответа, типичные ошибки, подсказки, решение
    base.py          Topic, Task, Malrule; точный разбор чисел
  tutor.py           проверка ответа с диагностикой, выбор задачи, интерактивный сеанс, отчёт
  bkt.py             обновление оценки освоения, выбор сложности
  profile.py         профиль ученика в JSON (атомарная запись, проверка формата)
  cli.py             командная строка
scripts/make_docs.py генератор docs/
tests/               80 тестов
```

Принципы, на которых всё держится:

- **Задачи детерминированы.** Задача определяется тройкой (тема, сложность, seed), поэтому её можно воспроизвести. Проверено в отдельных процессах при разных `PYTHONHASHSEED`.
- **Ответ всегда проверяется точно.** Числа хранятся как дроби, нет сравнений с плавающей точкой.
- **Нечитаемый ввод — не ошибка ученика.** Если вы опечатались (`abc`, `1/0`), попытка не списывается, и модель знаний это не учитывает.
- **Один ответ — одно наблюдение.** В BKT идёт одна запись на задачу: «верно с первой попытки и без подсказок» или нет.
- **Диагностика осторожна по формулировке.** Одно и то же число могут дать разные ошибки, а иногда и случайность, поэтому программа пишет «Похоже на типичную ошибку», а не утверждает. Если подходят несколько правил, показываются все.

## Как это проверено

80 тестов на стандартном `unittest`, запускаются за доли секунды: `python -m unittest discover -s tests -v`.

- **Задачи сверяются с независимыми реализациями.** Определитель с разложением Лапласа, комбинаторика с перебором через `itertools`, свойства отношений с определениями «в лоб», решение системы подстановкой в уравнения.
- **Диагностика проверена в обе стороны.** Для каждого «неверного правила» ответ, который оно даёт, распознаётся и получает своё объяснение. Каждое описанное правило встречается в реальных задачах. Значения неверных ответов для комбинаторики сверены с независимо записанным списком неверных формул, а для остальных тем проверены на заранее посчитанных примерах.
- **Модель знаний сверена с формулой Байеса**, посчитанной отдельно на точных дробях; проверены границы [0, 1] и сходимость.
- **Устойчивость к мусору.** Случайные строки подаются на разбор всех тем и не должны приводить к исключениям. Именно так нашёлся сбой на вводе `1/0`.
- **Профиль.** Круговая запись и чтение, повреждённый файл не перезаписывается, сбой посреди записи не портит старый профиль.
- **Сами тесты проверены.** Я внёс в код 26 типичных ошибок (перепутанный знак, сдвиг на единицу, пропущенное условие, неверные пороги) и убедился, что тесты падают на каждой. В первый раз выжило три, и для них добавлены проверки. Эта батарея проверяет тесты, а не доказывает отсутствие ошибок.

## Ограничения

- **Распознаётся только итоговый ответ.** Ход вашего решения программа не видит: она заметит «знак поменялся», но не скажет, на каком шаге. Арифметическая описка, не совпадающая ни с одним известным правилом, получит только «Неверно».
- Список типичных ошибок составлен мной по опыту учебных задач, а не выведен из данных реальных учеников.
- **Параметры BKT** (`p_init = 0.2`, `p_learn = 0.15`, `p_slip = 0.1`, `p_guess = 0.2`) выбраны как разумные значения по умолчанию, а не обучены на данных. Оценки освоения стоит читать как ориентир.
- Четыре темы, три уровня сложности, русский язык, один пользователь на файл профиля.
- Начатая и брошенная задача (например, выход после подсказки) засчитывается как неудача.

## Идеи для развития

- проверка **хода решения**: принимать промежуточные шаги и находить, где ошибка (естественно связывается с моим проектом mathsteps, который уже умеет строить эталонное решение по шагам);
- обучение параметров BKT и списка типичных ошибок на журналах реальных сеансов (профиль уже хранит историю);
- интервальные повторения: возвращать темы по графику забывания;
- языковая модель как *слой объяснения* поверх проверенной диагностики: она формулирует разбор, а правильность по-прежнему решает код.
